## Implementation

- Repository connect/index supplies the persisted symbol and semantic-edge graph used by the Code Universe canvas. File/symbol selection resolves the stored ego network and exact source/target line locations. The Settings dependency explorer uses persisted graph edges; its former payment example has been removed.
- The editor reads bounded, repository-contained UTF-8 source and submits its unsaved buffer to the daemon. The source tree is not written. Simulation results flow back to the graph for damaged callers, broken removed-export references, syntax diagnostics, and newly dead private/internal symbols.
- Unsupported file types are excluded from the incremental analyzer fast path and retain `Unknown`/`Partial` coverage; they are never reported as a verified pass.
- The canvas now treats the parent-provided focused symbol as the selection source of truth, avoiding a duplicate state update after graph interactions. Imperative WebGL state is synchronized in a layout effect, and a simulation already present on first mount is applied after the scene installs its overlay callback.
- The supported single-file path parses the draft once, reuses baseline artifacts and the connected repository's SQLite store, and avoids rebuilding/cloning the complete candidate graph. Impact traversal no longer performs an unused whole-graph SCC computation.
- Large seeded layouts use a deterministic bounded-work placement path. A 5,000-node layout regression checks one-run time and 100 repeated coordinate digests.
- The graph-universe endpoint now projects directly from SQLite instead of materializing every graph row in Rust. It returns at most 5,000 deterministic nodes (degree-ranked hubs plus a stable spread) and 12,000 prioritized edges, while preserving full graph totals, exact selected-node in/out degrees, full-graph coverage counts, and line provenance. A connection-local temporary table supports the selected-ID joins; no persistent schema or source files are changed.
- Large canvases use `THREE.Points` and `THREE.LineSegments` batches, a `1.35` device-pixel-ratio cap for dense graphs, and a deterministic 2,000-edge overview sample. This is bounded batching and sampling, not viewport-driven dynamic LOD; selecting a visible symbol still loads its full persisted ego network.
- Theme changes now register the Electron presentation mark synchronously before mutating the DOM, apply the root theme with transitions suppressed, and publish a separate measured DOM-mutation duration. Node status colors in both themes meet a 7:1 contrast ratio against the canvas background.

## Latest Implementation Delta — 2026-10-30

- Dense visual quality no longer uses the former `0.7x` renderer ratio or disabled dense-mode MSAA. The renderer now uses device-pixel ratio up to `2x`, always-on antialiasing, explicit sRGB output, 512px mipmapped card textures, up to 8x anisotropic filtering, and 68px screen-stable cards. The camera now targets the actual dense depth volume, using three deterministic module shelves instead of framing world origin. Light-theme module tints are softened while preserving legend identity, so the cards remain readable instead of becoming saturated blocks.
- Canvas startup is now independent from cockpit startup. `graphUniverse.worker.ts` performs streaming response reads, multi-megabyte JSON parsing, coordinate normalization, edge validation, and graph preparation outside the browser UI thread. `page.tsx` lazy-loads `CodeUniverse3D`, schedules graph work after the shell receives an idle opportunity, mounts the prepared graph through a React transition, rejects stale worker responses by request id, and aborts old work during repository switches or unmounts.
- The canvas owns an animated staged progress surface (`scheduled`, `requesting`, `downloading`, `parsing`, `preparing`, `transferring`, `mounting`) while the workspace rail, explorer, simulator, repository controls, header, and live-event UI remain mounted and interactive. This removes the previous all-or-nothing frontend loading dependency; it does not claim that backend cold indexing or the 5,000-node FPS target is solved.
- File selection now creates one dedicated world-space `THREE.Sprite` rather than trying to enlarge every fixed-pixel overview point. The focused card always faces the camera and renders the real filename, parent path, status, source range, caller count, and callee count at a 150-unit camera radius; the existing side profile remains open. This avoids thousands of per-file meshes or textures and preserves bounded overview batching.
- The focused sprite resolves the selected node's deterministic module assignment and uses the same active-theme legend color for its surface tint, border, file icon, status badge, and accent rule. Preview cards therefore retain real module identity instead of sharing a fixed cyan palette.
- Dense module groups now occupy deterministic staggered 3D shelves (four columns with row, column, and shelf depth offsets). File cards have wider horizontal/vertical spacing and deeper layers, removing the former coplanar wall while retaining a non-spherical mind-map topology and repeatable placement.
- Incremental simulation coverage is now scoped to the edited file and its relevant graph edges instead of being blocked by unrelated unsupported files in the repository. A live unchanged supported TypeScript buffer (`src/adb/AdbHostFileName.ts`) returned `PASS`, `coverage_state: verified`, no diagnostics, and preserved baseline/candidate snapshot ids; the release daemon computation took 34,319 ms on this large mixed repository. This does not convert unrelated Java/dynamic/unsupported files into a false pass.
- The dense canvas now derives deterministic document-card anchors from persisted symbol `file_path` values when the bounded graph projection contains symbols but no explicit file nodes. Cards preserve real paths and selection metadata; selecting a repository symbol in the live Electron shell opened the real `bridge/android/ReaJadxBridge.java` source range and coverage badge.
- Dense card placement is a bounded cluster lattice with deterministic columns, rows, and depth layers. It is a navigable mind-map/network layout, not a spherical force/particle layout. The restarted screenshot showed visible rounded document cards and relationship lines; the live shell exposed the card/path guidance and focus/search controls.
- Canvas drag direction is now consistent across dense and regular renderers: horizontal and vertical orbit/tilt deltas follow the pointer in 3D and 2.5D, and dense pointer-pan uses the same grab-to-move direction as the regular renderer.
- Dense overview no longer renders symbol particles. It deterministically collapses real semantic edges onto their source and target file cards, removes same-file self-links, deduplicates repeated file relationships, and applies the module legend color to each card.
- Synthetic `file:<path>` card selection now resolves to the real repository path, opens the existing details/profile drawer, aggregates its persisted symbol-level incoming/outgoing edges, and zooms the camera to a local preview radius instead of retaining the full-graph scale.
- File-card profile aggregation now normalizes both explicit `file_path` values and persisted `file::<path>` records, and also uses edge source/target file provenance so file-level callers and callees are not lost when a bounded projection omits file metadata on a symbol row.
- Electron WSL child-process launches now set `windowsHide: true`, preventing the Next/daemon terminal window from covering the production cockpit during a cold shell start.
- The shared dense card texture now uses a larger rounded document surface, a visible folded-file icon, and a shorter path hint so cards remain legible at the bounded overview scale without reintroducing symbol particles.

Native presentation readings in the live 5,000-node shell remained approximately 27.7–50.4 FPS in observed samples, so the independent `>=60 FPS` acceptance target is still not claimed.
